# Estado de completitud del frontend y límites operativos

Corte al **2026-11-18** frente al contrato [OpenAPI 0.11.0](../../backend/docs/api/openapi.yaml)
(`FIN-01`) y las guías en `backend/docs/`. Este documento separa lo que ya funciona conectado a la
API real de lo que opera con respaldo local o permanece pendiente de implementación en interfaz.

## Resumen por bloque funcional

## Reglas operativas vigentes para el frontend

1. **Stripe no está habilitado para uso operativo**: Aunque la API define `POST /orders/{id}/checkout`, el backend mantiene Stripe deshabilitado en servidor/worker (`503`) hasta completar revisión y pruebas externas. No habilitar flujo de pago real con tarjeta en producción hasta recibir confirmación de backend.
2. **Cloudinary simulado en backend**: Las rutas `/admin/products/{id}/image-upload` y `/image` devuelven `503` sin credenciales reales configuradas. La UI administrativa aún no implementa el selector de archivos ni el flujo de dos pasos.
3. **No depender de `localStorage` como fuente de verdad**: Los respaldos en `taffy_*` y `coffees_*` sirven para tolerar desarrollo sin API, pero pueden ocultar errores HTTP (por ejemplo, en `ShiftWorkspace` o `HistoryWorkspace` donde un error silencioso muestra datos vacíos o locales).
